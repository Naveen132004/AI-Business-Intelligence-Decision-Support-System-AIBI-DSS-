# Deploying AIBI-DSS on Render (free)

Everything here runs on free plans:

| Part | Where | Plan |
| ---- | ----- | ---- |
| Website (React) | Render **static site** `aibi-dss-web` | Free |
| API (Spring Boot) | Render **web service** `aibi-dss-api` (Docker) | Free, 512 MB |
| AI service (FastAPI) | Render **web service** `aibi-dss-ai` (Python) | Free, 512 MB |
| Database (Postgres + pgvector) | **Neon** | Free, doesn't expire |

The services are defined in [`render.yaml`](render.yaml), so Render creates all three in one go.

**How it fits in 512 MB:** on Render the AI service uses Gemini for embeddings
(`EMBEDDING_PROVIDER=gemini`) and installs `requirements-render.txt`, which leaves out
PyTorch. Measured under a 512 MB cap: AI service ≈ 185 MB, API ≈ 220 MB.
Locally nothing changes — it still uses the built-in embedding model.

**What "free" means in practice**

- Free web services **sleep after 15 minutes without traffic**. The first visit after that
  takes about a minute while the API wakes up; after that it's normal speed.
- Render gives **750 free instance-hours per month per workspace**, shared by all your free
  services (including your other project). Sleeping services don't use hours, so a
  demo/portfolio project stays well within it.
- Why not Render's own Postgres? The free Render database is **deleted after 30 days**.
  Neon's free tier keeps your data.

## 1. Create the database on Neon

1. Sign up at <https://neon.tech> (you can use your GitHub account).
2. **Create project** → name `aibi`, Postgres **16**, region **AWS Asia Pacific (Singapore)**
   (same region as the Render services, so queries are fast).
3. Open **SQL Editor**, paste the whole contents of [`db/init.sql`](db/init.sql), and click **Run**.
   This creates the tables, the `vector` extension and the admin user.
4. Click **Connect** on the project dashboard. Turn **Connection pooling off** (use the direct
   connection — the API's database driver doesn't work well through the pooler).
   Keep this page open; you need these values in step 2:

   | Render asks for | What to paste | Example |
   | --------------- | ------------- | ------- |
   | `DATABASE_URL` (AI service) | the connection string as shown | `postgresql://neondb_owner:AbC123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require` |
   | `DB_URL` (API) | same host and database, in JDBC form, **without** user/password | `jdbc:postgresql://ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require` |
   | `DB_USER` (API) | the user | `neondb_owner` |
   | `DB_PASSWORD` (API) | the password | `AbC123` |

## 2. Create the services on Render

1. In the Render dashboard: **New → Blueprint**.
2. Connect the GitHub repo
   `Naveen132004/AI-Business-Intelligence-Decision-Support-System-AIBI-DSS-` (branch `main`).
3. Render reads `render.yaml` and lists `aibi-dss-api`, `aibi-dss-ai`, `aibi-dss-web` and the
   environment group `aibi-dss-shared`. Fill in the values it asks for:
   - `DB_URL`, `DB_USER`, `DB_PASSWORD`, `DATABASE_URL` — from the Neon table above
   - `GEMINI_API_KEY` — from <https://aistudio.google.com/apikey> (needed for the assistant;
     you can leave it empty and add it later)
4. Click **Apply**. The first deploy takes about 10 minutes (the API's Docker build is the slow part).

`JWT_SECRET` and `INTERNAL_API_KEY` are generated by Render automatically. The internal key
lets only your API call the AI service, because free services must talk over public URLs.

## 3. Check the service URLs

When the deploy finishes, open each service and look at its URL. If all three are exactly

- `https://aibi-dss-web.onrender.com`
- `https://aibi-dss-api.onrender.com`
- `https://aibi-dss-ai.onrender.com`

you're done. If Render added a suffix to any name (it does when a name is already taken
by someone else), update these to the real URLs:

| Service | Setting | Set it to |
| ------- | ------- | --------- |
| `aibi-dss-api` → Environment | `CORS_ALLOWED_ORIGINS` | the web URL |
| `aibi-dss-api` → Environment | `AI_SERVICE_URL` | the AI service URL |
| `aibi-dss-web` → Redirects/Rewrites | rule for `/api/*` | `<api URL>/api/*` |

Better still, change them in `render.yaml` and push, so the Blueprint stays in sync.

## 4. Open the app and secure it

1. Open the web URL. If it says it can't reach the server, wait a minute (the API is waking up) and retry.
2. `db/init.sql` creates `admin@aibi.com` with the public password `Admin@123`.
   **Sign in, go to Profile, and change that password right away.**
3. For the assistant: make sure `GEMINI_API_KEY` is set on `aibi-dss-ai`, then open
   **Assistant → Sync data** once to index your data.

---

## Updating

Push to `main` — Render redeploys the services automatically.

## Troubleshooting

| Symptom | Check |
| ------- | ----- |
| Site loads but sign-in says "Network error" | API still waking up (wait ~1 min); then `aibi-dss-api` → **Logs** |
| API logs show database connection errors | `DB_URL` must start with `jdbc:postgresql://` and end with `?sslmode=require`; user/password go in `DB_USER`/`DB_PASSWORD`; pooling off in Neon |
| Forecast / health score fail | `aibi-dss-ai` → Logs; `AI_SERVICE_URL` on the API points to the AI service's real URL |
| AI service logs "Missing or invalid internal key" | Both services must use the `aibi-dss-shared` group (don't override `INTERNAL_API_KEY` on one of them) |
| Assistant: "GEMINI_API_KEY is not configured" | Add the key on `aibi-dss-ai` → Environment, then Sync data |
| Assistant errors about a model not found | Google renamed a model — set `GEMINI_MODEL` / `GEMINI_EMBEDDING_MODEL` on `aibi-dss-ai` to a current name |
| Deploy of `aibi-dss-api` runs out of memory | Keep the `JAVA_OPTS` value from `render.yaml` |
